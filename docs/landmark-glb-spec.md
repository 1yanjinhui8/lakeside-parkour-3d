# 地标 GLB 建模规格书

给美术的交付规范。按这份做，模型丢进 `assets/landmarks/` 就能自动接进游戏，
不需要改任何代码——槽位、广场、台基、324m 循环、昼夜光效都由接入层处理。

---

## 一、交付什么

7 个文件，文件名**必须完全一致**（区分大小写）：

| 文件名 | 地标 | 位置 | 真实高度 | 识别特征（不能丢） |
|---|---|---|---|---|
| `pearl.glb` | 上海东方明珠 | 左 s0 | 468m | 三球不等径（1 : 0.72 : 0.52）+ 三根外倾斜撑 + 尖顶 |
| `guomao.glb` | 北京国贸三期 | 左 s3 | 330m | 方塔三段阶梯收分 + 顶部暖色灯笼冠 + 四角竖棱 |
| `bamboo.glb` | 深圳春笋 | 左 s6 | 392m | 六段连续锥度（底/顶 3.5 : 1）+ 竹节箍 + 笋尖 |
| `gateSuzhou.glb` | 苏州东方之门 | 左 s9 | 302m | 双腿**向内收**（底跨 15.2→顶 5.4）+ 顶部合拢成实体 |
| `gateHangzhou.glb` | 杭州之门 | 右 s1 | 310m | 双腿**竖直平行** + 顶部弧形连桥，整体是「H」+ 通透的洞 |
| `waist.glb` | 广州塔「小蛮腰」 | 右 s4 | 600m | 外张基座收腰（腰比 0.42）+ 左右旋斜交网格 |
| `cbd.glb` | 北京国贸 CBD 群 | 右 s7 | 330m | 4 栋高低错落的塔群 + 共用裙房 + 锯齿顶线 |

放这里：

```
assets/landmarks/
├── pearl.glb
├── guomao.glb
├── bamboo.glb
├── gateSuzhou.glb
├── gateHangzhou.glb
├── waist.glb
└── cbd.glb
```

**可以分批交付**。没放的会自动用代码生成的版本，不会白屏、不会报错，控制台只打一行
`[landmark] xxx 没有 GLB，回退代码生成`。

## 二、坐标系（最容易出错的一节）

| 项 | 要求 | 说明 |
|---|---|---|
| 单位 | **米** | 不要用厘米或英尺 |
| 原点 | **底面中心**，即 `(0, 0, 0)` 是塔脚正中央 | 接入层会把包围盒的 `min.y` 对齐到地面、`center.x/z` 对齐到轴心，但原点在底面中心时最省事、也最不容易出意外 |
| 朝向 | **正面朝 −X** | 即「门」类地标的开口朝向 −X 方向。接入时会按街道左右自动转 180°，你不用管左右 |
| 轴向 | Y 轴向上 | 和 Blender / glTF 的默认一致 |
| 缩放 | 应用变换（Apply Scale/Rotation） | 根节点上不要留未应用的变换，否则归一化会按错误包围盒算 |
| 旋转 | 根节点旋转归零 | 同上 |

**关于「正面朝 −X」**：只有 `gateSuzhou` 和 `gateHangzhou` 这两座「门」需要在意朝向——
它们的开口要朝向街道。其余五座基本轴对称，朝向无所谓，但统一按这个来最省事。

## 三、尺寸

**不用按真实高度建**。接入层会自动缩放到统一目标高度，你只要保证**比例正确**。

| 项 | 数值 | 说明 |
|---|---|---|
| 目标高度 | **54 m**（从 4m 台基顶算起） | 接入层自动缩放到这个值，你的模型多高都行 |
| X 向占地 | **≤ 16 m**（硬上限） | 街宽只有 7.6m、路缘在 \|x\|=3.8、人行道到 \|x\|=10.6，地标轴心在 x=±12。超了会压到马路上 |
| Z 向进深 | ≤ 22 m | 广场进深 26m，超过会穿到隔壁槽位 |

超过 16m 时接入层会**按宽度再缩一次**（高度就不足 54m 了），并在控制台警告
`超宽已按 16m 收缩`。所以建模时就压进 16m，别让它触发兜底。

参考：现在代码生成的地标，X 向占地分别是
`pearl 13.6 / waist 10.4 / bamboo 10.4 / guomao 13 / cbd 22（这个例外，它是群楼）/ gateSuzhou 15.2 / gateHangzhou 15.4`。

## 四、面数与贴图预算

| 项 | 预算 | 超了会怎样 |
|---|---|---|
| 单个模型三角面 | **≤ 16,000** | 控制台警告，手机上会掉帧 |
| 7 座合计 | ≤ 90,000 | — |
| 贴图总尺寸 | 单张 ≤ 1024×1024 | 建议 512 或 1024；4K 贴图会把文件推到几十 MB |
| 单模型文件体积 | ≤ 2.5 MB | 内联进 `playable.html` 时 base64 会膨胀 33% |

**为什么卡这么死**：整个城市街区（24 栋塔 + 7 座地标 + 街道装饰）现在只有约 1.5 万面。
7 座地标如果各做 5 万面，总面数会从 16.6 万涨到 50 万，手机端直接崩。

如果确实需要更精细：优先做**剪影**（外轮廓、顶部造型），砍掉看不见的背面和内部结构。
远处 200m 外只能看到剪影，内部结构完全浪费。

## 五、材质命名（决定夜里怎么亮，最重要的一节）

接入层**按材质名分类**，分类决定这个材质挂哪条昼夜发光曲线。
名字不对 = 夜里不亮，或者亮错档位。

| 材质名包含 | 分类 | 接入后的行为 |
|---|---|---|
| `window` / `win` / `glass` / `curtain` | **窗格** | 保留你的贴图，把贴图当 `emissiveMap`，夜里 emissive 从 0.08 涨到 0.42（冷）或 0.10→0.48（暖） |
| `neon` / `glow` / `halo` / `light_bar` / `led` | **霓虹** | 换成不受光照影响的纯色材质，夜里亮度 0.30→0.92，**保留你设的颜色** |
| `trim` / `frame` / `edge` / `rib` / `mullion` | **收边** | 深色结构件，夜里 0.05→0.19 |
| 其他（默认） | **主体** | 大面积塔身，夜里 0.06→0.25，**永远低于车道线的 0.82** |

**冷暖窗**：窗格材质名里带 `warm` / `amber` / `gold` / `orange` 就是暖光，
否则按冷光（青蓝）处理。例如：

```
window_warm      → 暖窗（琥珀色，0.10→0.48）
window_cool      → 冷窗（青蓝色，0.08→0.42）
neon_cyan        → 青色霓虹
neon_amber       → 琥珀霓虹
tower_mass       → 主体
tower_trim       → 收边
```

**命名示例（推荐照抄）**：

| 部件 | 材质名 |
|---|---|
| 塔身大面积 | `tower_mass` |
| 幕墙玻璃（冷） | `window_cool` |
| 幕墙玻璃（暖） | `window_warm` |
| 顶部灯笼 / 冠体 | `crown_glass_warm` |
| 结构收边 / 檐口 | `tower_trim` |
| 竖向光带 | `neon_cyan` / `neon_violet` / `neon_amber` |
| 顶部灯环 | `neon_ring` |

## 六、材质参数建议

接入层会保留你设的 `baseColor` / `metallic` / `roughness`，只改 `emissive`。
按这个范围调，和现有街景最协调：

| 分类 | baseColor | metallic | roughness |
|---|---|---|---|
| 主体塔身 | 深蓝灰 `#1d2a3a` ~ `#36495f` | 0.35 ~ 0.40 | 0.55 ~ 0.62 |
| 窗格 | 深蓝 `#16202c` ~ `#1a2431` | 0.25 ~ 0.35 | 0.42 ~ 0.50 |
| 收边 | 近黑 `#0a0e15` | 0.70 | 0.45 |
| 霓虹 | 任意饱和色 | 0（反正会换 basic 材质） | — |

**不要烘焙光照**（Bake Lighting / 静态阴影）。游戏的昼夜是实时的，
烘焙进去的明暗会在白天变成死黑块。明暗交给引擎。

**不要用顶点色代替贴图**：接入层不会处理顶点色，会丢。

---

## 七、贴图规范

| 项 | 要求 |
|---|---|
| 格式 | PNG 或 JPG，嵌入 GLB（不要外链） |
| 尺寸 | 512×512 或 1024×1024，**2 的幂** |
| 通道 | 窗格贴图请把「亮着的窗」画在 `baseColor` 里，接入层会直接拿它当 `emissiveMap` |
| 色温 | 暖窗用琥珀/橙黄（`#ffd68c` 附近），冷窗用青蓝（`#bfe9ff` 附近），别用纯白 |
| 透明度 | 不要用 alpha 做窗格（会有排序问题），用颜色深浅表示亮暗 |

**窗格贴图怎么画最省事**：一张 512×512 上画 6 列 × 12 行窗格，
亮窗用目标色，暗窗用深蓝（`#16202c`），窗框留 2~3 像素深色线。
接入层会把它当 `emissiveMap`，所以**亮窗在夜里会自己发光**，暗窗不会。

---

## 八、禁止事项

| 不要 | 原因 |
|---|---|
| 骨骼 / 动画 | 地标是静态的，骨骼只会增加体积和加载时间 |
| 多材质 mesh（一个 mesh 挂多个 material） | 能加载，但会多出 drawcall。**一个 mesh 一个材质**最好 |
| InstancedMesh / 粒子 / Sprite | 会被「按材质大合并」的处理逻辑误判，可能被静默丢弃 |
| 外部贴图文件（`.png` 放 GLB 旁边） | 单文件发布版没有相对路径，贴图必须嵌进 GLB |
| 烘焙光照 / 静态阴影 | 昼夜是实时的，烘焙进去白天会变成死黑块 |
| 根节点带未应用的缩放/旋转 | 归一化会按错误包围盒计算，模型会变形 |

## 十、常见问题

**Q：我的模型很高（比如按 468m 建的），会被缩成什么样？**
A：接入层按包围盒高度等比缩放到 54m，宽度同比例缩。只要原始比例对，结果就对。

**Q：能不能只做部分模型？**
A：可以。没交付的自动用代码版本，混着跑没问题。但两套视觉风格差异会很明显，
建议同一批交付。

**Q：夜里全黑怎么办？**
A：检查材质名。名字里没有 `window` / `neon` / `trim` 关键词的都会归到「主体」，
夜里上限只有 0.25——这是刻意的（防止地标把路面照糊）。想更亮就把对应部件
命名成 `neon_xxx`。

**Q：能不能给 GLB 加自发光材质（emissive）？**
A：可以，但接入层会**覆盖** `emissive` 和 `emissiveIntensity`（因为要接昼夜曲线）。
你只需要保证 `baseColor` 和贴图对，亮度交给引擎。

**Q：`cbd.glb` 是「一群楼」，怎么做成一个模型？**
A：做成一个 GLB，里面 4~6 个 mesh 各一栋楼，共用 2~3 个材质。
接入层会把整组当一个地标处理，缩放和朝向一致。
